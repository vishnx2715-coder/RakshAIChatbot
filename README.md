# RAKSHA — National Disaster Intelligence Platform

AI-powered disaster awareness and emergency guidance for India. Built with Flask, Groq LLaMA 3.3 70B, Supabase, OpenWeatherMap, GDACS, and Leaflet maps.

---

## Features

- **Live weather risk** — OpenWeatherMap + multi-hazard scoring (cyclone, flood, heatwave, fog, thunderstorm)
- **Global disaster alerts** — GDACS, ReliefWeb, WHO, EMSC, UN OCHA RSS feeds
- **AI assistant** — Multilingual (22 Indian languages + English) powered by Groq LLaMA 3.3 70B
- **Shelter finder** — Nominatim/OSM nearby shelter search with OSRM/ORS routing
- **Disaster guidelines** — NDMA-sourced safety guidelines for 20 disaster types
- **Auth** — Email/password (argon2id) + Google OAuth with legacy SHA-256 upgrade

## Environment Variables

Copy `.env.example` to `.env` and fill in values. **Never commit `.env`.**

| Variable | Required | Description |
|---|---|---|
| `SECRET_KEY` | ✅ | Flask session signing key — generate with `python -c "import secrets; print(secrets.token_hex(32))"` |
| `GROQ_API_KEY` | ✅ | [console.groq.com](https://console.groq.com) — free tier available |
| `OPENWEATHER_API_KEY` | ✅ | [openweathermap.org/api](https://openweathermap.org/api) — free tier |
| `SUPABASE_URL` | ✅ | Supabase project URL — Settings → API |
| `SUPABASE_KEY` | ✅ | Supabase anon/service_role key (NOT management key) |
| `GOOGLE_CLIENT_ID` | optional | OAuth 2.0 Web client ID — enables Google Sign-In |
| `GOOGLE_MAPS_KEY` | optional | Maps JavaScript API key |
| `ORS_API_KEY` | optional | [openrouteservice.org](https://openrouteservice.org) — 2000 req/day free |
| `REDIS_URL` | optional | `redis://localhost:6379` locally; Render internal URL in prod |
| `FLASK_ENV` | optional | Set to `production` on Render (automatically done via render.yaml) |

## Run Locally

```bash
# 1. Clone and install
git clone <repo-url>
cd RakshAiChatbot
pip install -r requirements.txt

# 2. Set up environment
cp .env.example .env
# Fill in your keys in .env

# 3. (Optional) Start Redis for caching
docker compose up -d redis

# 4. Run dev server
flask --app app run --debug
# App available at http://localhost:5000
```

## Deploy on Render

1. Push to GitHub.
2. Create a new **Web Service** on [render.com](https://render.com), connect repo.
3. Render auto-detects `render.yaml` — build and start commands are pre-configured.
4. In the Render dashboard → Environment, set all `sync: false` variables.
5. `SECRET_KEY` is auto-generated by Render (`generateValue: true`).
6. (Optional) Add a **Redis** instance on Render, copy the internal URL to `REDIS_URL`.

Start command (from `render.yaml`):
```
gunicorn "app:create_app()" --workers 3 --timeout 60
```

## Redis Setup

Redis is **optional** — the app falls back to direct API fetches when Redis is unavailable.

**Local (Docker):**
```bash
docker compose up -d redis
# Then add to .env:
REDIS_URL=redis://localhost:6379
```

**Render production:**
1. Render dashboard → New → Redis
2. Copy the **Internal Redis URL**
3. Set as `REDIS_URL` environment variable on your web service

**Cache TTLs:**
| Cache | Key | TTL |
|---|---|---|
| RSS news feeds | `raksha:rss:news` | 300 s |
| GDACS events | `raksha:gdacs:events` | 600 s |
| India weather risk | `raksha:india:risk` | 300 s |

## Security Notes

- Passwords hashed with **argon2id** (RFC 9106 defaults). Legacy SHA-256 hashes upgrade transparently on next login.
- Session cookies: `HttpOnly=True`, `SameSite=Lax`, `Secure=True` in production.
- Rate limits: register 10/hr, login 20/hr, google-auth 20/hr, chat 60/hr.
- Google ID tokens verified server-side with explicit audience check (`aud == GOOGLE_CLIENT_ID`).
- No stack traces exposed in production responses.
- All secrets loaded from environment — zero hardcoded values in codebase.
